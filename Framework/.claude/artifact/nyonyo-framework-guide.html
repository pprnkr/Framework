Nyonyo Framework 가이드

Unity 2D 게임 공용 프레임워크의 기능과 사용법입니다. 2026-10-27 기준이며, Unity 6000.3 이상에서 동작합니다.

개요와 상태

게임이 시작되면 Bootstrapper가 첫 씬보다 먼저 실행됩니다. 이때 게임별 GameInstaller가 서비스를 등록하고, 게임 코드에서는 Services.Get<T>()로 꺼내 씁니다. 다른 기능도 모두 이 서비스 구조 위에 올라갑니다.

다른 프로젝트에 설치

Package Manager에서 + › Install package from git URL을 선택하고 아래 주소를 입력합니다.

https://github.com/pprnkr/Framework.git?path=/Framework/Packages/com.nyonyo.framework#v0.1.0

1. 설정 파일 만들기

메뉴 Tools › Nyonyo Framework › Create Settings를 실행합니다. 그러면 Assets/Resources/NyonyoFrameworkSettings.asset이 생깁니다.

2. 게임 Installer 만들기

현재 기능을 모두 쓰는 기본 템플릿입니다. 에셋으로 만든 뒤 설정 파일의 Installers 목록에 추가하세요.

using Nyonyo.Framework;
using Nyonyo.Framework.Assets;
using Nyonyo.Framework.Audio;
using Nyonyo.Framework.Debugging;
using Nyonyo.Framework.Events;
using Nyonyo.Framework.Inputs;
using Nyonyo.Framework.Pooling;
using Nyonyo.Framework.Save;
using Nyonyo.Framework.Scenes;
using Nyonyo.Framework.Timing;
using Nyonyo.Framework.UI;
using UnityEngine;

[CreateAssetMenu(menuName = "MyGame/Game Installer")]
public class MyGameInstaller : GameInstaller
{
    [SerializeField] UISettings _uiSettings;
    [SerializeField] SoundSettings _soundSettings;

    public override void Install(ServiceRegistry services)
    {
        // 다른 서비스가 쓰는 기반 서비스를 먼저 등록합니다(정리할 때 가장 나중에 정리됨).
        var events = new EventBus();
        services.Register<IEventBus>(events);

        var assets = new AssetLoader();
        services.Register<IAssetLoader>(assets);

        var save = new SaveService();
        services.Register(save);

        services.Register(new PauseService(events));
        services.Register(new TimerService(Bootstrapper.Root));
        services.Register(new PoolManager(Bootstrapper.Root));
        services.Register(new InputService(save: save, initialMap: "Player"));

        services.Register<ISceneService>(
            new SceneService(new FadeTransition(Bootstrapper.Root), events));
        services.Register(new PopupManager(_uiSettings, Bootstrapper.Root, events, assets));
        services.Register(new SoundManager(_soundSettings, Bootstrapper.Root, assets, save));
        services.Register(new DebugConsole(Bootstrapper.Root));
    }
}

부트스트랩 · 서비스 관리 검증됨

Runtime/Core · Nyonyo.Framework

시스템을 인터페이스로 등록하고 어디서든 꺼내 씁니다. 싱글톤 대신 쓰는 구조라서 구현을 갈아 끼우거나 테스트하기 쉽습니다.

서비스 만들기

public interface ISaveService { void Save(); }

public class JsonSaveService : ISaveService, IAsyncInitializable, IDisposable
{
    public async Awaitable InitializeAsync(CancellationToken cancellationToken)
    {
        // 세이브 파일 로드 같은 비동기 초기화
    }

    public void Save() { }
    public void Dispose() { /* 종료 시 정리 */ }
}
인터페이스호출 시점
IInitializable초기화 단계 (동기)
IAsyncInitializable초기화 단계 (비동기). 끝날 때까지 다음 서비스가 기다립니다.
IDisposable게임 종료, Play 모드 종료

사용하기

Services.Get<ISaveService>().Save();

if (Services.TryGet(out ISaveService save))
    save.Save();

// 비동기 초기화가 끝날 때까지 기다리기
await Bootstrapper.WaitUntilReadyAsync();

// MonoBehaviour 서비스는 씬이 바뀌어도 유지되는 Root에 붙입니다.
var audio = Bootstrapper.Root.gameObject.AddComponent<AudioService>();
  • 순서: 등록 순서대로 초기화되고, 그 역순으로 정리됩니다. 초기화 중에 다른 서비스를 쓴다면 그 서비스를 먼저 등록하세요.
  • 실패: 서비스 하나가 초기화에 실패하면 거기서 멈춥니다. 이미 초기화된 서비스만 정리됩니다.
  • 정리 순서: 종료할 때는 서비스가 씬 오브젝트보다 먼저 정리됩니다. 그래서 OnDestroy와 OnDisable에서는 Services.TryGet을 쓰세요.

이벤트 검증됨

Runtime/Events · Nyonyo.Framework.Events

시스템끼리 직접 참조하지 않고 이벤트로 소식을 주고받습니다. 예를 들어 플레이어가 죽으면 UI, 사운드, 저장 시스템이 각자 PlayerDied를 받아서 반응합니다.

// 이벤트 정의: struct + IEvent
public readonly struct PlayerDied : IEvent
{
    public readonly int PlayerId;
    public PlayerDied(int playerId) => PlayerId = playerId;
}

// 발행
Services.Get<IEventBus>().Publish(new PlayerDied(id));

// 구독: 오브젝트가 파괴되면 자동으로 해제됩니다.
void Start()
{
    Services.Get<IEventBus>().Subscribe<PlayerDied>(OnPlayerDied, destroyCancellationToken);
}

// 직접 해제하고 싶을 때
IDisposable _sub;
void OnEnable()  => _sub = Services.Get<IEventBus>().Subscribe<PlayerDied>(OnPlayerDied);
void OnDisable() => _sub?.Dispose();
  • 메모리: 이벤트를 발행할 때 메모리를 할당하지 않습니다. 매 프레임 발행해도 됩니다.
  • 호출 순서와 예외: 핸들러는 구독한 순서대로 호출됩니다. 핸들러 하나가 예외를 던져도 나머지 핸들러는 계속 호출됩니다.
  • 발행 중 구독 변경: 발행 도중에 새로 구독한 핸들러는 다음 발행부터 호출됩니다. 아직 호출되지 않은 핸들러를 해제하면 이번 발행에서도 호출되지 않습니다.
  • 스레드: 메인 스레드에서만 사용하세요.

씬 관리 확인 필요

Runtime/Scenes · Nyonyo.Framework.Scenes

진행 순서는 다음과 같습니다.

  1. SceneLoadStarted 발행
  2. 화면 가리기 (페이드 아웃)
  3. 씬 로드
  4. SceneLoaded 발행
  5. 화면 보이기 (페이드 인)
// 등록 (Installer)
var transition = new FadeTransition(Bootstrapper.Root);            // 검은색, 0.3초
var scenes = new SceneService(transition, events) { MinimumLoadingSeconds = 0.3f };
services.Register<ISceneService>(scenes);

// 사용
await Services.Get<ISceneService>().LoadAsync("Stage1");

// 상태
bool loading = scenes.IsLoading;
float progress = scenes.Progress;   // 0~1
  • Scene List 등록: 씬은 File › Build Profiles › Scene List에 추가되어 있어야 합니다.
  • 중복 요청: 전환 중에 다시 요청하면 무시하고 경고를 띄우며 false를 반환합니다.
  • SceneLoaded 핸들러: 이 핸들러가 불리는 시점에는 아직 전환 중입니다. 그래서 핸들러 안에서 바로 다른 씬을 불러오면 무시됩니다.
  • 페이드 동작: 페이드는 일시정지(timeScale = 0) 중에도 동작하고, 가리는 동안 UI 클릭을 막습니다.

확장 포인트

인터페이스용도
ISceneTransition로딩 화면(진행률 바) 같은 다른 전환 연출을 만듭니다. ShowAsync, SetProgress, HideAsync를 구현합니다.
ISceneLoaderAddressables처럼 다른 방식으로 씬을 불러옵니다. 기본은 SceneManagerLoader입니다.

UI · 팝업 확인 필요

Runtime/UI · Nyonyo.Framework.UI

UI를 5개 층으로 나눕니다. 높은 층은 항상 낮은 층 위에 보이고, 같은 층에서는 나중에 띄운 것이 위에 보입니다. 그래서 일반 팝업이 여러 개 떠 있어도 띠알람은 그 위에 나옵니다.

Screen메인 메뉴, HUD · 1000
Popup일반 팝업 · 2000
System확인창, 네트워크 오류 · 3000
Notice띠알람, 토스트 · 4000
Top로딩 인디케이터, 디버그 · 5000
Scene Fade씬 전환 페이드 · 30000

클래스 구조

클래스담당
UIBase모든 UI의 기본. 표시/숨김(Show, Hide, OnShow, OnHide), 버튼 이벤트(public virtual OnButtonEvent(Button)), 자동 매핑 대상
PopupBase : UIBase팝업. 층, 뒤로가기, 닫기(Close, OnOpen, Closed, WaitUntilClosedAsync)

팝업 안에서 따로 동작하는 큰 UI 묶음(탭, 목록 항목 등)은 UIBase를 상속한 별도 스크립트로 만들어 자식 오브젝트에 붙입니다.

1. 팝업 만들기

PopupBase를 상속한 컴포넌트를 프리팹 루트에 붙입니다. 이때 루트는 Canvas가 아닌 일반 RectTransform이어야 합니다. 직접 작성해도 되지만 UI 자동 매퍼로 만드는 걸 추천합니다.

using Nyonyo.Framework.Assets;
using Nyonyo.Framework.UI;
using UnityEngine.UI;

// PopupManager가 이 경로와 방식으로 프리팹을 불러옵니다.
[Popup(Path = "Assets/Popups/PopupTest.prefab", LoadType = LoadType.Addressables)]
public class PopupTest : PopupBase
{
    protected override void OnOpen()
    {
        // 생성 직후 초기화
    }

    // 버튼 OnClick에 연결하면 모든 버튼 클릭이 여기로 모입니다.
    public override void OnButtonEvent(Button button)
    {
        switch (button.name)
        {
            case "BTN_Ok":
                Close();
                break;
            default:
                base.OnButtonEvent(button);
                break;
        }
    }

    public override void Close()
    {
        // 닫히기 전에 할 일
        base.Close();                         // 반드시 호출: 여기서 Destroy됩니다
    }
}
[Popup] 값설명
LoadType.AddressablesPath는 address입니다. 기본 address는 에셋 경로(Assets/.../X.prefab)입니다.
LoadType.ResourcesPath는 Resources 폴더 기준 경로이고 확장자를 뺍니다(예: Popups/Loading). 게임 시작에 꼭 필요한 팝업에만 씁니다.

자동 매퍼(Create UI Script › Popup)로 만들면 이 값이 프리팹 위치에 맞춰 자동으로 들어가고, Addressables에도 자동으로 등록됩니다.

인스펙터 항목설명
Layer기본으로 뜰 층
Back KeyClose는 닫기, Block은 막기(아래 팝업도 안 닫힘), Ignore는 건너뛰기(띠알람용)
Close On Scene Change씬이 바뀔 때 자동으로 닫을지 여부
버튼 클릭은 자동으로 연결되지 않습니다 Button의 OnClick에 OnButtonEvent를 연결하고 인자로 그 Button을 넘기세요. Assign Object를 쓰면 BTN_ 버튼은 자동으로 연결됩니다. 닫기 버튼은 OnClick에 Close를 직접 연결해도 됩니다.

2. 등록하기

  1. Create › Nyonyo Framework › UI Settings로 에셋을 만듭니다.
  2. 기준 해상도를 설정합니다. 기본값은 1920×1080이고, 세로 게임이라면 1080×1920으로 바꾸세요. 프리팹 목록은 따로 없습니다. 각 팝업의 [Popup]으로 불러옵니다.
  3. Installer에서 new PopupManager(_uiSettings, Bootstrapper.Root, events, assets)를 등록합니다.

프리팹은 처음 Show할 때 불러오고 그 뒤로는 재사용합니다. Show는 Addressables를 WaitForCompletion으로 바로 불러오는데, WebGL에서는 이 방식을 쓸 수 없습니다. 그래서 WebGL에서는 ShowAsync나 PreloadAsync를 쓰세요.

3. 사용하기

// 띄우기 (프리팹에 설정된 층)
var popup = PopupManager.Instance.Show<PopupTest>();

// 비동기로 불러와서 띄우기, 미리 불러 두기
var shop = await PopupManager.Instance.ShowAsync<PopupShop>();
await PopupManager.Instance.PreloadAsync<PopupShop>();

// 층 직접 지정
PopupManager.Instance.Show<PopupTest>(UILayer.System);

// 띠알람: Notice 층 프리팹이면 팝업 위에 뜹니다.
PopupManager.Instance.Show<PopupNotice>().SetMessage("저장되었습니다");

// 닫힐 때까지 기다리기 (확인창 응답 등)
await popup.WaitUntilClosedAsync();
popup.Closed += p => Debug.Log("closed");

// 조회, 닫기
PopupManager.Instance.IsOpen<PopupTest>();
PopupManager.Instance.Find<PopupTest>();         // 가장 위 인스턴스
PopupManager.Instance.CloseAll(UILayer.Popup);    // 층 생략 시 전부

// 뒤로가기로 닫을 팝업이 없을 때 (게임 종료 확인창 등)
PopupManager.Instance.BackKeyUnhandled += ShowQuitDialog;

// 팝업이 아닌 UI(HUD)를 층 규칙으로 그리기
hud.SetParent(PopupManager.Instance.GetLayerRoot(UILayer.Screen), false);
  • PopupManager.Instance: Services.Get<PopupManager>()의 줄임말입니다. 싱글톤이 아니라서 도메인 리로드를 꺼도 안전합니다.
  • 메모리 해제: Close()는 팝업을 Destroy합니다. 닫힌 팝업은 메모리에 남지 않습니다.
  • 뒤로가기: ESC와 안드로이드 뒤로가기는 가장 위 팝업부터 Back Key 설정대로 처리합니다.
  • EventSystem: Play 중에 EventSystem이 없으면 PopupManager가 만들어서 유지합니다. 씬에는 EventSystem을 두지 마세요.

UI 자동 매퍼 확인 필요

Editor/UI · Nyonyo.Framework.Editor.UI (에디터 전용)

프리팹의 게임오브젝트 이름에 접두사를 붙여 두면, 그 오브젝트를 담는 변수를 스크립트에 자동으로 만들고 연결합니다.

1. 새 스크립트 만들기

  1. 프리팹을 구성하면서 오브젝트 이름에 접두사를 붙입니다. 예: IMG_A, TXT_B, BTN_Ok.
  2. Project 창에서 프리팹을 선택하거나 프리팹 모드를 연 상태에서 메뉴를 실행합니다.
    • Tools › Create UI Script › Popup: PopupBase를 상속합니다.
    • Tools › Create UI Script › UI: UIBase를 상속합니다. 팝업 안에서 쓰는 자식 UI용입니다.
  3. 저장 위치 창에서 경로를 고릅니다. 파일 이름은 프리팹 이름이 기본값이고, 파일 이름이 곧 클래스 이름이 됩니다.
  4. 컴파일이 끝나면 스크립트가 프리팹 루트에 자동으로 붙고, 오브젝트도 변수에 자동으로 연결됩니다.
using Nyonyo.Framework.UI;
using TMPro;
using UnityEngine;
using UnityEngine.UI;

public class Test : PopupBase
{
    #region Auto Generated UI
    #pragma warning disable CS0169, CS0649
    [SerializeField] private Image IMG_A;
    [SerializeField] private TextMeshProUGUI TXT_B;
    [SerializeField] private Button BTN_Ok;
    #pragma warning restore CS0169, CS0649
    #endregion

    protected override void OnOpen()
    {
    }

    public override void OnButtonEvent(Button button)
    {
        switch (button.name)
        {
            case "BTN_Ok":
                break;
            default:
                base.OnButtonEvent(button);
                break;
        }
    }
}

2. 인스펙터 버튼

UIBase를 상속한 모든 컴포넌트(팝업 포함)의 인스펙터에 나타납니다.

버튼동작
Generate Script현재 자식 오브젝트로 #region Auto Generated UI 영역만 다시 씁니다. 영역 밖에 직접 쓴 코드는 그대로 남습니다. 스크립트가 바뀌면 컴파일 후 자동으로 연결합니다.
Assign Object접두사 오브젝트를 같은 이름의 변수에 연결합니다. BTN_ 버튼은 OnClick에 OnButtonEvent도 연결합니다. 이미 연결된 것은 다시 추가하지 않습니다.

3. 접두사 규칙 (UIPrefixSettings)

처음 사용할 때 Assets/Editor/UIPrefixSettings.asset이 만들어집니다. 접두사를 추가하거나 바꿀 수 있고, 타입은 전체 이름으로 적습니다. 인스펙터에서 찾을 수 없는 타입을 알려 줍니다.

Runtime/Assets · Nyonyo.Framework.Assets

Resources와 Addressables를 같은 인터페이스(IAssetLoader)로 불러옵니다. 게임 시작에 꼭 필요한 최소한의 에셋만 Resources에 두고, 나머지는 Addressables를 씁니다.

var assets = Services.Get<IAssetLoader>();
var icon = await assets.LoadAsync<Sprite>("Assets/Icons/Gold.png", LoadType.Addressables);
var logo = assets.Load<Sprite>("UI/Logo", LoadType.Resources);   // Resources/UI/Logo.png

// 다 쓰면 반환 (Addressables는 불러온 횟수만큼)
assets.Release("Assets/Icons/Gold.png", LoadType.Addressables);
  • 패키지: Addressables 4.1.1(2026-10 기준 최신, Unity 6000.0 이상)에 의존합니다. 프레임워크를 설치하면 함께 설치됩니다.
  • Play 모드: 에디터 Play 모드는 Addressables Groups 창의 Play Mode Script가 Use Asset Database(기본값)이면 빌드 없이 동작합니다.
  • 에디터 등록: AddressableEditorUtility.SetAddress(assetPath, address)로 에셋을 등록합니다.
  • Resources 반환: Resources 에셋은 Release가 아무 일도 하지 않습니다. 정리하려면 Resources.UnloadUnusedAssets를 쓰세요.

사운드 확인 필요

Runtime/Audio · Nyonyo.Framework.Audio

BGM과 효과음을 이름으로 재생합니다. 이름은 SoundSettings의 경로 형식(기본 BGM/{0}, SFX/{0})으로 바뀌어서 불러옵니다.

1. 사운드 준비

  1. 사운드 파일을 Assets/Sounds/BGM, Assets/Sounds/SFX에 넣습니다. 폴더는 SoundSettings에서 바꿀 수 있습니다.
  2. Create › Nyonyo Framework › Sound Settings로 설정 에셋을 만듭니다.
  3. Tools › Nyonyo Framework › Sound › Register Sounds to Addressables를 실행합니다. 그러면 Assets/Sounds/BGM/Title.wav가 address BGM/Title로 등록됩니다.

Load Type을 Resources로 바꾸면 Resources/BGM, Resources/SFX에 두기만 하면 됩니다.

2. 사용하기

SoundManager.Instance.PlayBGM("Title");                      // BGM/Title
SoundManager.Instance.PlayBGM("Battle", fadeSeconds: 1f);    // 1초 크로스페이드
SoundManager.Instance.StopBGM(1f);

SoundManager.Instance.PlaySFX("Hit");                        // SFX/Hit
SoundManager.Instance.PlaySFX("Coin", 0.5f);                 // 이 효과음만 절반 볼륨

// 볼륨 (0~1) — 설정 팝업의 슬라이더와 연결
SoundManager.Instance.MasterVolume = 0.8f;
SoundManager.Instance.BgmVolume = 0.5f;
SoundManager.Instance.SfxVolume = 1f;
SoundManager.Instance.VolumeChanged += RefreshSliders;

// 첫 재생 지연 없애기, 메모리 정리
await SoundManager.Instance.PreloadSFX("Hit", "Coin");
SoundManager.Instance.UnloadAllSFX();
종류실제 볼륨
BGMMasterVolume × BgmVolume × 재생 volume
효과음MasterVolume × SfxVolume × 재생 volume
  • 볼륨 반영: 볼륨을 바꾸면 재생 중인 소리에도 바로 반영됩니다.
  • 동시 재생 수: 효과음은 기본 8개까지 동시에 들립니다. 다 차면 가장 오래된 효과음을 끊고 재생합니다(SoundSettings의 SFX Channels로 바꿀 수 있음).
  • 같은 BGM 재요청: 이미 재생 중인 BGM을 다시 요청하면 처음부터 틀지 않고 볼륨만 바꿉니다.
  • 메모리: 효과음은 UnloadSFX/UnloadAllSFX 전까지 메모리에 남고, BGM은 바뀌거나 멈추면 내려갑니다.
  • 사운드를 찾지 못할 때: 예외 대신 에러 로그를 남깁니다.
  • 볼륨 저장: 볼륨 저장은 저장 시스템을 만들 때 연동할 예정입니다.

저장 확인 필요

Runtime/Save · Nyonyo.Framework.Save

데이터를 키 단위로 저장합니다. 진행 데이터는 세이브 슬롯에, 설정은 전역에 둡니다. 기본 저장소는 WebGL이면 PlayerPrefs, 그 밖은 persistentDataPath/Saves 파일입니다.

services.Register(new SaveService());

[Serializable]
public class PlayerData { public int gold; public string nickname = ""; }

var save = SaveService.Instance;
save.CurrentSlot = 1;
save.Save("player", data);                                // 슬롯 1
var loaded = save.Load("player", new PlayerData());       // 없으면 기본값
save.Save("settings", settings, SaveScope.Global);        // 슬롯과 상관없음

save.SlotExists(1);
save.TryGetSlotInfo(1, out var info);                     // LastSavedUtc, KeyCount
save.DeleteSlot(1);
  • 저장 시점: Save는 호출 즉시 기록합니다. WebGL은 종료 시점을 알 수 없으므로, 종료할 때 한꺼번에 저장하지 마세요.
  • 데이터 형식: JsonUtility 규칙을 따릅니다. [Serializable] 클래스의 public 필드나 [SerializeField] 필드만 저장되고, Dictionary와 프로퍼티는 저장되지 않습니다. int, string, 배열은 클래스로 감싸세요.
  • 구조 변경: 구조가 바뀌면 IVersionedSaveData를 구현합니다. 예전 데이터를 불러오면 Migrate(fromVersion) 뒤 다시 저장됩니다.
  • 안전성: 파일은 임시 파일에 쓴 뒤 바꿔치기하므로 쓰는 도중 꺼져도 깨지지 않습니다. 손상된 데이터는 에러 로그를 남기고 기본값을 돌려줍니다.
  • 볼륨과 키 설정: SoundManager, InputService에 SaveService를 넘기면 볼륨과 키 설정이 자동으로 저장됩니다.

런타임 코드는 스레드와 Task 없이 Unity Awaitable만 써서 WebGL에서 동작합니다. 실제 WebGL 빌드는 아직 하지 않았습니다(WebGL 모듈이 설치돼 있지 않음). 대신 플레이어용 엔진 DLL과 UNITY_WEBGL 심볼로 컴파일해서 확인했습니다.

항목내용
Addressables 동기 로드WebGL은 WaitForCompletion을 지원하지 않습니다. Show로 바로 띄울 Addressables 팝업은 [Popup(Preload = true)]로 두거나 ShowAsync를 쓰세요. 동기 로드를 시도하면 원인을 알려 주는 예외가 나고, 에디터의 빌드 대상이 WebGL이면 미리 경고합니다.
종료 처리탭을 닫으면 Application.quitting이 호출되지 않습니다. 저장, 볼륨, 키 설정은 바뀔 때 바로 저장됩니다.
저장소PlayerPrefs(브라우저 IndexedDB)를 쓰고, 전체 1MB 정도로 제한됩니다.
소리브라우저 정책상 사용자가 처음 클릭하거나 키를 누르기 전에는 소리가 나지 않습니다. "터치해서 시작" 같은 입력을 받은 뒤 BGM을 트세요.
ESC 키전체 화면에서는 브라우저가 ESC를 먼저 가져갑니다. 뒤로가기는 버튼으로도 할 수 있게 하세요.

꼭 지킬 규칙

도메인 리로드가 꺼져 있습니다 (Enter Play Mode: Reload Scene only) static 필드, static event, 싱글톤 Instance가 이전 Play의 상태를 그대로 들고 옵니다. 그러니 서비스와 EventBus를 쓰세요. 꼭 static이 필요하다면 [RuntimeInitializeOnLoadMethod(SubsystemRegistration)]에서 초기화하세요.
  • 등록 순서: EventBus는 Installer에서 가장 먼저 등록합니다.
  • 종료 시 서비스 접근: OnDestroy와 OnDisable에서는 Services.TryGet을 씁니다.
  • EventSystem: 씬에 EventSystem을 두지 않습니다. PopupManager가 관리합니다.
  • 팝업 경로: 팝업 클래스에는 [Popup(Path, LoadType)]을 붙입니다. 프리팹을 옮기면 경로도 고칩니다. 인스펙터가 경로가 다르다고 경고해 줍니다.
  • 에셋 위치: Resources에는 게임 시작에 꼭 필요한 에셋만 두고, 나머지는 Addressables로 불러옵니다.
  • 팝업 프리팹: 팝업 프리팹 루트에 Canvas를 두지 않습니다. 같은 층 정렬은 형제 순서로 정하기 때문입니다.
  • Close 재정의: PopupBase.Close()를 재정의하면 마지막에 base.Close()를 호출합니다.
  • 자동 생성 영역: #region Auto Generated UI 안은 Generate Script가 덮어씁니다. 직접 쓰는 코드는 영역 밖에 두세요.
  • .meta 커밋: 패키지 파일의 .meta는 반드시 커밋합니다. 없으면 git으로 설치할 때 에러가 납니다.

문제 해결

에디터가 "Running Backend"에서 멈춤

Unity를 강제로 종료하면 컴파일 프로세스(bee_backend.exe)가 남을 수 있습니다. 그러면 다음 실행이 막힙니다. 아래 순서로 해결하세요.

  1. Unity를 끕니다.
  2. 작업 관리자에서 bee_backend, BeeLocalCacheTool, VBCSCompiler를 종료합니다.
  3. Unity를 다시 엽니다.

로그 위치는 %LOCALAPPDATA%\Unity\Editor\Editor.log입니다.
